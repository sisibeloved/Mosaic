# 1. 概述

## 1.1 简介

Mosaic 的核心优化目标是**单位 token 与轮次的新增认知价值**，不是发言量。本 RFC 定义实现该目标度量的框架：确定性回放（固定 Event fixture 重建投影与决策路径，模型非确定性已被事件固化，回放不重调模型）、六组指标目录、在线/离线白名单（bridge rate、跨 Agent 密度、收束率等永不进入在线 Floor 奖励——11.3 的执行面）、人工标注基线与噪声下限（OQ-10 建议）、A/B 与校准门流程（承接 RFC-0003 的 OQ-15 校准门）。评测先于调参：没有基线的阈值调整一律不允许收紧。

## 1.2 动机

架构 §6.8/§6.10.5 列出了指标清单与反 Goodhart 原则，但四个缺口：指标定义未精化到可计算、人工标注基线未设计（OQ-10 未决）、"不进在线奖励"缺执行机制、回放确定性的边界未定义。多个 RFC 的裁决建议（0003 权重、0005 quorum、0006 阈值）都声明"以评测为准"——本 RFC 是这些承诺的兑现场所。

## 1.3 目标

### 1.3.1 目标

1. 定义回放框架：fixture 结构、确定性边界、一致性断言；
2. 定义指标目录（六组，含定义、数据来源、在线/离线属性）；
3. 定义反 Goodhart 执行面：在线白名单、延迟确认、组合指标原则；
4. 定义人工标注基线流程与噪声下限（OQ-10 裁决建议）；
5. 定义 A/B 与 feature flag 流程及校准门联动；
6. 定义评测数据 Schema 与指标版本化；
7. 定义同构折算与独立收敛的评测口径。

### 1.3.2 非目标

- 在线学习/奖励（永久禁止，架构 §1.2 明确排除）；
- 产品级 analytics/商业指标（观测归运维）；
- 标注平台工程与众包管理（工具选型 ADR）；
- 具体阈值的标定结果（本 RFC 只定流程，结果随实验产出）。

# 3. 方案设计

## 3.1 总体方案

### 3.1.1 回放框架

- **fixture 结构**：`{events.ndjson（Envelope 序列）, decisions.jsonl（Intent 原始记录、选择特征、Policy/权重版本、结果指标）, expected/（投影期望产出与决策期望）}`；
- **回放语义**：从空库重建投影（RFC-0006 一致性门禁）→ 以已记录决策重放确定性路径（评分/选择/quorum/合格性）→ 与 expected 对比；
- **确定性边界**：模型调用不在回放内（其输出已固化为事件/Intent）；一切确定性组件（评分、MMR、quorum、合格性、预算）必须同输入同输出（tie-break 可种化，0003）；
- **断言层级**：逐位一致（决策序列）、集合一致（投影对象）、容差一致（延迟/资源指标 ±10%）。

### 3.1.2 指标目录（六组）

| 组 | 指标 | 来源 | 属性 |
|---|---|---|---|
| 效率 | 发言采纳率、token/轮次、单轮延迟、失败率、手动停止率 | model_runs + Attention 事件 | 离线+面板 |
| 内容质量 | 重复度、视角覆盖度、分歧发现率、点名命中率、错误插话率 | Intent + 投影 | 离线 |
| 结构 | 跨 Agent 密度（按有效 typed relation 与 token/message 归一）、bridge_rate（仅诊断）、**bridge_yield**、交替链衰减 | RFC-0006 投影 | 离线；yield 为延迟确认 |
| 收束 | **dissent_survival**、**closure_stability**（遗漏型重开与真新证据重开分开计）、Evidence Request 解决率、人工修订率 | Closure 事件族 | 离线 |
| 公平 | floor share 分布、长期沉默偏差、dyad_share 命中率、frontier slot 使用率 | Attention 事件 | 面板诊断 |
| 独立收敛与人类信号 | **independent_convergence**（冻结水位首轮 vs cross 后；含弱独立折算）、引用/保存、bridge 导航、Capsule 接受/修订、明确评价、后续决策采纳 | 多源 | 离线 + opt-in 采集 |

加粗为反 Goodhart 核心指标（延迟确认 + 组合使用）。

### 3.1.3 反 Goodhart 执行面

1. **在线白名单**：进入在线路径的量仅限"硬资格/预算/可见性"类；`bridge_rate`、跨 Agent 密度、收束率、novelty 类结构信号只作离线评测与诊断面板——**任何新指标进入在线 Floor 路径需独立 RFC 修订并附人工基线**（11.3 的可执行化）；
2. **延迟确认**：productive 才计入分子（bridge_yield）、真新证据重开才计入 stability 分母；
3. **组合原则**：单一结构指标不得单独成为任何在线决策输入（0003 已把结构特征限定为组合输入）。

### 3.1.4 人工标注基线（OQ-10 裁决建议）

| 标注任务 | 问题形态 | 产出 |
|---|---|---|
| bridge productive | 该桥接是否带来新认知价值？（三选一：是/否/不确定） | bridge_yield 人工基线 |
| dissent 保留 | Capsule 摘要是否忠实保留该异议？ | dissent_survival 基线 |
| closure 稳定 | 该次重开源于遗漏还是真新证据？ | closure_stability 分型基线 |
| 人类结果信号 | 该发言/收束对用户有用吗？（opt-in 显式评价样本） | 人类信号锚点 |

- **噪声下限**：标注者 ≥2；Cohen's kappa ≥ 0.6 视为可用基线，低于则任务定义返工而非取均值；
- **裁决建议**：任何运行时阈值的收紧（0003 公平机制、0006 聚类参数、0005 quorum）必须在变更记录中引用已达标的基线；基线每季度复核（漂移检测）。

### 3.1.5 A/B 与校准门

- 载体：feature flag（Policy 版本化参数天然支持分组）；对照维度登记（reveal 策略、公平机制开关、horizon 可见性、投影版本）；
- 顺序：离线回放对比先行 → 在线 A/B 需门禁（样本量预估、分组均衡、用户告知策略）；
- 校准门（承接 0003 OQ-15）：收紧类变更 → 引用基线；放宽类/回退类 → 自由（安全方向默认宽松门槛）。

### 3.1.6 评测数据 Schema

- `evaluation_run`：`{run_id, fixture_ref | online_window, mosaic_version, policy_versions, algorithm_versions, metrics_snapshot（版本化）}`；
- 指标版本化：每个指标带 `metric_version`（定义变更即升版，历史不可比不对比）；
- 精确分与内部特征仅存评测库（与用户可见 band 承诺隔离，0003）。

### 3.1.7 同构折算口径

- independent_convergence 计算：取 simultaneous/independent_then_cross 轮的冻结水位首轮立场 vs cross 后立场（0005/0003 语义）；
- 同构组（同 provider+model）、共享上下文、首发锚定三种弱独立来源分别标记，聚合时按 0005 quorum 同口径折算（组内计一）；
- 该口径同时供 0005 收束元数据与 0006 stance 标记消费，三处必须同源。

## 3.2 技术选型

| 决策点 | 选择 | 放弃方案与原因 |
|---|---|---|
| 评测执行 | CI 内 Go 测试 + fixture 仓 | 独立评测平台：v0.1 规模不需要 |
| 指标计算 | SQL/Go 内聚批处理 | 流式指标引擎：延迟无需求 |
| 标注协作 | 表格 + 导出任务格式 | 标注平台：流程未稳前先固化任务定义 |
| 面板 | v0.1 静态报告（JSON/HTML 导出） | Web 面板：先有口径后有面板 |

## 3.3 功能与性能设计

- **内部端口原型**：`EvalPort: Replay(fixture) -> Report / ComputeMetrics(window) -> Snapshot / Compare(runs) -> Diff / ExportAnnotationTasks() -> tasks`；
- **性能目标**：全量回放（抽样策略：每 Room 抽 10% 轮次全量 + 关键轮全量）CI < 10 分钟；指标批处理按 Room 分片；
- **影响范围**：CI 门禁（回放一致性、决策逐位一致）、评测库、诊断报告导出、基线归档。

## 3.4 安全隐私与 DFX 设计

- **隐私**：人类信号采集 opt-in、最小化；评测库访问按 0008 审计；不含 prompt/隐藏推理；
- **防拟合**：精确分不出评测库；Agent 可见的只有 band（0003）；
- **可复现**：评测 run 全量版本化（代码/Policy/算法/fixture），任何报告可重算；
- **诚实性**：背离告警不自动改参（人工决策），避免评测系统本身成为隐藏优化器。

## 3.5 编程与调用设计

### 3.5.1 编程模型基本设计

- **开发环境**：fixture 仓 + 本地 `eval` CLI（replay/metrics/compare/annotate 四命令）；
- **开发约束**：新指标必须登记目录（含 metric_version 与在线/离线属性）；未登记指标不得进面板；
- **可验收设计**：回放一致性、指标可重算、白名单静态检查（CI 扫描在线路径引用的指标集合）。

### 3.5.2 接口定义与设计

#### Replay（评测 CLI/端口）

接口描述：对 fixture 执行重建 + 决策重放 + 断言。

接口原型：`EvalPort.Replay(fixture_ref) -> Report{assertions, diffs}`

输入/输出参数：

| 参数名称 | 输入/输出 | 类型 | 描述 | 取值范围 |
| --- | --- | --- | --- | --- |
| fixture_ref | 输入 | string | fixture 版本指针 | 仓内登记 |
| assertions | 输出 | object | 三层断言结果（逐位/集合/容差） | — |
| diffs | 输出 | object | 不一致明细（定位到事件/决策） | — |

- 异常处理：断言失败即 CI 失败，输出最小复现集。
- 约束说明：回放内禁止网络与模型调用（静态检查）。
- 变更说明：首版。
- 调用参考代码：`mosaic-eval replay --fixture cases/room-basic-001`。

#### ComputeMetrics / Compare

接口描述：窗口指标批计算与跨 run 对比。

接口原型：`EvalPort.ComputeMetrics(window) -> Snapshot`；`EvalPort.Compare(a, b) -> Diff`

- 异常处理：窗口数据缺失按缺失标记，不填充默认值。
- 约束说明：指标版本不一致不直接对比（提示升版对齐）。
- 变更说明：首版。
- 调用参考代码：`mosaic-eval compare run-a run-b`。

#### ExportAnnotationTasks

接口描述：导出人工标注任务包（含最小上下文与判分说明）。

接口原型：`EvalPort.ExportAnnotationTasks(kind, window) -> tasks`

- 约束说明：任务包脱敏（仅必要上下文）；kappa 回收入口。
- 变更说明：首版。
- 调用参考代码：`mosaic-eval annotate --kind bridge_yield --export`。

# 4. 缺点和风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 指标代理失真（结构指标≠认知价值） | 系统被导向错误方向 | 延迟确认 + 组合指标 + 人类信号锚点 + 背离告警 |
| 回放成本随事件增长 | CI 退化 | 抽样策略 + 分片 + 关键轮全量 |
| 标注质量不足（kappa 低） | 基线不可用 | 任务返工机制而非均值掩盖 |
| 在线/离线口径漂移 | 指标误读 | metric_version + 同源计算代码 |
| 评测系统自身被优化（Agent 适配评测） | 数据污染 | 评测 fixture 不进任何在线上下文；精确分不出评测库 |

# 5. 现有技术

| 参考 | 借鉴 | 差异 |
|---|---|---|
| Goodhart 定律 / 卢卡斯批判 | 度量即失真的理论基础 | Mosaic 以白名单 + 延迟确认工程化应对 |
| 离线强化学习评测（固定数据集） | 不与环境交互的决策评估语义 | Mosaic 回放"已发生决策"而非反事实 |
| A/B 实验工程（分层/均衡/样本量） | 在线对照的门禁实践 | Mosaic 先离线后在线的强制顺序 |
| 引文影响分析（延迟指标） | productive 类延迟归因 | bridge_yield 的方法论来源 |
| 众包标注质量控制（kappa/一致性） | 噪声下限机制 | Mosaic 用"返工而非均值"策略 |
