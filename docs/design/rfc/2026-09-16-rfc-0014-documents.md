# 1. 动机与范围

群聊讨论产生的结论与素材需要沉淀为**可复用、可接续编辑的资产**：一个 agent 起草的文档，人类与其他 agent 能在后续讨论中直接引用、继续修改，而不是靠复制粘贴传递文本（对标 tutti 内置文档 app 的"产物在 agent 间流转"；体验对标飞书文档）。

范围（单人本地形态）：

- markdown 块级文档，workspace 级**全局资产**（不隶属于单一房间）；
- 房间消息流中的**文档卡片**（引用式，原地刷新）与**群文档**（attached 列表）；
- **文档管理**：文档主页、全文搜索、版本历史与回滚、归档/删除/副本/导出；
- agent 经结构化 `doc_ops` 块读写文档（memory_ops 引擎校验代写先例平移）。

明确不在本 RFC 范围：多人实时协同编辑（CRDT/OT，归云端形态演进）、**表格**（公式引用偏移与结构操作变换是独立深水区，另行立项）、富文本重依赖编辑器（TipTap 等）、文件夹层级 / 模板库 / 权限矩阵（单用户无协作者）、文档语义检索。

# 2. 语义设计

## 2.1 定位裁定：为什么是"一等主体 + 引用卡片"

三路线对比（2026-09-16 负责人裁定取 B）：

| 路线 | 存储 | 致命伤 |
|---|---|---|
| A. 附件形态 | 不可变文件 + 版本链 | 是"文件传递"非"协作文档"：无块级冲突粒度、无段落锚点、卡片无法原地刷新 |
| **B. 一等主体 + 引用卡片（采用）** | 独立文档聚合 + 自身事件流；消息携带 doc_ref，卡片为**投影** | — |
| C. 消息卡片形态（飞书的存储模型） | 内容嵌 message payload / 改消息 | 与"消息是不可变事实"直接冲突；高频编辑要么触发 agent 反应波、要么给引擎开特例 |

关键理念：**文档是共享可变状态，消息是不可变事实**。卡片原地更新不靠改消息——消息只携带 `doc_id`，前端订阅文档当前态（投影），日志追加、卡片自新。

## 2.2 数据模型

文档元数据（派生态，权威为事件流）：

- `doc_id`（`doc_<12hex>`，服务端生成）、`title`（≤200 runes）、`format`（首版封闭枚举 `markdown`）、`created_by`（human 或 bot participant）、`created_at`、当前 `version`、生命周期状态（active / archived；删除走墓碑先例）。

正文 = **有序 block 列表**，block 有稳定 `block_id`：

- `type ∈ {heading, paragraph, list, code, quote, hr}`（首版封闭集；表格块随表格立项另行裁定）；
- `text`（markdown 行内语法）；
- block 模型是 agent 锚定操作、冲突重放与卡片摘要的共同基础——纯文本 + 行区间方案在 agent DSL 上不可行（裁定，不再回摆）。

## 2.3 文档事件流（per-doc stream）

文档变更**不进房间事件日志**，落在每文档一条的事件流（存储与 CAS 裁定见 [ADR-0014](../adr/ADR-0014-document-event-stream.md)）：

| 事件 | 载荷要点 |
|---|---|
| `doc.created` | doc_id, title, format, created_by, anchor_message_id? |
| `doc.renamed` | doc_id, title |
| `doc.revision_committed` | doc_id, base_version, version, ops[], actor, source ∈ {human_editor, agent}, note? |
| `doc.archived` / `doc.restored` | doc_id |
| （删除） | 墓碑先例：元数据删除事件 + 内容级联清除，事件留痕 |

- **修订批语义**：`ops` 是一批 block 操作（`insert_after(block_id|null)` / `replace(block_id, text)` / `delete(block_id)` / `append`）。人类编辑器按防抖（建议 1–2s）或块提交聚合成一批——**事件频率与聊天消息同量级，不做每击键一条**（快照全量重放的既有成本模型不被击穿，M5 物化快照不被迫提前）。
- **文档级并发**：`base_version` 不符 → 拒绝并返回当前 version 与当前态，客户端在新态上重放本地未提交 ops。单人 + agent 经引擎串行代写，真实冲突面只有"人类编辑中 agent 落笔"一组，块级 op 重放大多天然成功，**不引入 OT/CRDT**（多人实时协同归云端形态）。
- `version` 单调递增，天然充当文档级 SSE cursor。

## 2.4 房间关联：引用与附着

- **消息引用**：`message.posted` 载荷新增可选 `refs` 数组（先例：附件描述子），项 `{kind:"doc", doc_id, anchor_block_id?}`。分享文档到房间 = 发一条带 doc_ref 的消息（人类或 agent 均可）。
- **群文档（attached）**：房间事件 `doc.attached_to_room` / `doc.detached_from_room`（房间日志内的**关联事实**，非文档内容），驱动房间右面板"文档"段；附着不复制、不锁定，同一文档可附着多个房间。
- 文档不随讨论分支分叉（thread fork 不分叉文档）；Closure/Pause Capsule 可钉 `doc_id@version` 作证据引用。

## 2.5 消息卡片（飞书体验的投影实现）

- 带 doc_ref 的消息渲染为**文档卡片**：标题、前 N 行摘要、当前 version、最近更新时间与更新者（人 / agent）；按钮：打开（编辑器页）/ 引用（输入区 @）/ 历史。
- 卡片数据来自文档投影：SSE `doc:{id}` 频道推送 revision → 所有引用该文档的卡片**原地刷新** + "有更新"徽标；消息事件本体永不被修改。
- 卡片按钮动作走既有 HTTP 命令通道，无新机制。

## 2.6 SSE 频道化

订阅枢纽从单一房间流扩展为多频道：`room:{id}`（现状）+ `doc:{id}`（新增；cursor = doc_version；断线续传、慢消费者断流 + `resync_required` 语义同既有 hub）。房间流**不**冗余转发文档事件——编辑器与卡片直接订 doc 频道。

## 2.7 Agent 读写面

- **写**：结构化输出块新增 `doc_ops`（create / append / replace_section / insert_after / delete_section；引擎逐 op 校验 block 锚点、大小上限、schema 后代写事件，actor 记为该 bot——memory_ops 代写先例平移）。
- **透明纪律（裁定）**：agent 的 `doc_ops` **必须与公开说明消息同波发布**（"我重写了第 3 节……" + doc_ref 卡片）——时间线保住叙事性与可审计性，契合记分卡透明原则。
- **读**：① contextx 新增"被引用/附着文档摘录"层（有界，见 2.9；按引用注入，不全量灌入）；② `history_request` 两段式先例扩展 `doc_query`：agent 声明检索意图，引擎次波注入命中文档的标题 / 摘要 / 指定块——**全局资产必须可被发现**，否则跨房间复用落空。
- 人类编辑文档**不触发**反应波（引擎只对 `message.posted` 调度的既有纪律覆盖新事件族）；`doc.revision_committed` 摘要进观察语境"近期文档活动"，下一波自然可见。

## 2.8 文档管理（飞书云文档的单人本地版）

- **文档主页**：一级导航"文档"——全部文档列表（标题 / 当前版本 / 最近更新时间与更新者 / 关联房间徽标），创建者筛选（我 / 各 agent），更新时间排序。
- **全文搜索**：复用 storage 既有 FTS5 trigram 设施（记忆检索同型），标题 + 正文派生索引。
- **版本历史**：版本时间轴、相邻版本 diff 预览；**回滚 = 以旧版本内容为 ops 提交一条新 revision**（append-only，历史永不改写）。
- **生命周期**：归档 / 恢复、删除（墓碑 + 内容级联清除）、创建副本、导出 `.md`。
- **反向视图**：文档主页可跳转引用它的房间上下文；卡片反显"已在 N 个房间被引用"。

## 2.9 上限与护栏（建议值，负责人可裁）

| 项 | 建议上限 | 理由 |
|---|---|---|
| 单文档正文 | 256 KiB | 本地协作文档的实用上界；超限建议拆分 |
| 单条 revision ops 数 / 批体 | 64 ops / 128 KiB | 防抖批的合理上界；命令体 1MiB 既有约束内 |
| 语境注入摘录 | 每文档 8k runes | 与附件摘录同型护栏（§2.7） |
| 房间附着文档数 | 32 | 右面板与语境摘要的实用上界 |

# 3. 安全与隐私

- 文档命令面过既有写门三件套（Origin / Content-Type / X-Owner-Token）；`doc:{id}` SSE 频道同 owner-only。
- 文档内容注入语境前过 DLP 同款秘密形状剔除（私钥块 / bearer / sk- 前缀——附件摘录既有纪律平移：文档同样可能含密钥）。
- 删除走墓碑先例：内容级联清除（含 FTS5 索引项），事件留痕不含正文。
- agent 对文档的唯一写面是 `doc_ops` 引擎代写——不开放命令通道，既有"agent 不能发起房间命令"的边界不被本 RFC 改变。

# 4. 兼容与迁移

- 全部为新事件族与新命令，无存量迁移；旧客户端忽略未知 refs 字段（回放容错既有纪律）。
- NDJSON 导出包含 doc 事件流（每文档一段，含版本链）；备份面"副本即拷贝"天然覆盖（同一 SQLite 库，ADR-0014）。
- 房间删除不级联删文档（全局资产），仅解除附着；消息内 ref 渲染降级（卡片显示"文档已删除"）。

# 5. 里程碑与工作量（单人全栈估算）

| 里程碑 | 内容 | 估算 |
|---|---|---|
| 前置 | ADR-0014 + 本 RFC 定稿、事件 / schema / fixture 骨架 | ~1 周 |
| M1 文档核心 | 存储 + 聚合 + HTTP 契约 + SSE 频道化；块编辑器（markdown 块级，不引重框架）；消息卡片 + 房间文档面板；agent `doc_ops` + contextx 摘录层 | 5–7 周 |
| M2 文档管理 | 文档主页、FTS5 全文搜索、版本历史与回滚、归档/删除/副本/导出、`doc_query` 检索 | 2–3 周 |

主要风险：块编辑器是前端首个编辑类组件（自绘块编辑器，不引重框架）；其余各环节均有仓内先例（FTS5 / 墓碑 / 导出 / history_request / SSE hub / memory_ops 代写）。

# 6. 开放问题（评审点）

- **OQ-1 op 集定稿**：§2.3 的四种 op 是否够用（merge / split block 需求待编辑器实现时实证）。
- **OQ-2 卡片摘要生成**：取前 N 行纯文本即可，还是值得一次 summarize 任务（建议首版纯截取，不烧 token）。
- **OQ-3 物化触发条件**：doc 当前态纯折叠重放起步；revision 数超阈值（建议 500）再物化派生表——阈值待实测校准。
- **OQ-4 表格**：明确后置；立项时重新评估 Univer 集成 vs 自绘 grid + 公式引擎（2026-09 调研结论另存评审记录）。
