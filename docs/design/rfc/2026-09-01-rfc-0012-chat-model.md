# 1. 动机与差距

v1.27 交付的自动续聊仍是"会议制"语义：轮是结构与单位，引擎是主持人（评估→选人→发言→散会，链按轮数上限收口）。负责人愿景是"群聊制"：**消息流是连续的，没有轮次边界；每个 agent 是群聊参与者，对每条消息自主执行 观察→判断→回复，沉默是自己的决定**。差距是交互模型级的，不是参数级的。

# 2. 模型语义

## 2.1 触发：去抖反应窗口（owner 裁定）

- 任何 `message.posted`（**人类或 agent**）落地即调度该房间的**反应窗口**（默认 3s，`EngineConfig.ReactionWindow` 可注入，测试可置 0）。
- 窗口内新消息到达 → 重置计时并**重锚**（以最新消息为锚）；到期后以"最新语境"开一个**反应波**。
- 去抖的理由：意图评估即一次 CLI 调用（10–20s + token）；严格逐条在人类连发或双 agent 快速互答时产生评估风暴。体感仍是逐条应答（窗口远短于生成时长）。

## 2.2 反应波（round 的内部化）

- 每波仍是事件流上的 `round.opened → intent.recorded* → floor.granted → message.posted* → round.closed`——**协议骨架不变**（事件溯源、epoch、CAS 迟到拒绝、崩溃恢复、预算账本全部原样生效），但 round 从用户可见结构降为内部记账：**快照 Timeline 不再收录 round.\***，仅开发者模式可见。
- 波内流程：对全部在席座位做意图评估（观察→判断）→ **action ∈ {speak, react} 者全部放行**（无 max_speakers、无中央选人）→ 按记分卡分排序 sequential 发布（**逐发言人生成时刷新语境**——后发者可见同波先发消息与波中人类插话；生成前按新水位重验，迟到围栏保留）→ 每条发布再开新窗口。
- **自决**：`silent` 是 agent 的合法决定，intent.recorded 全记录（R-01 保留——记分卡可查"谁选择了沉默"）。

## 2.3 终止与节流（附录 F 修订：对话环检测整体退役，结构闸唯一）

| 机制 | 语义 |
|---|---|
| 意愿静默 | 一波内全员 silent → `round.closed(quiescent)` → 不再开窗，流自然终止。**无轮数上限**（auto_rounds 退役）；双边辩论等长链讨论是目标场景，链长不设上界 |
| 暂停 | 人类随时掐断 |

## 2.4 保留机制（语义平移）

- **@点名**：被点名者发布前置 + 记分卡特征（B3 定向通道的群聊化简写，交锋链深度机制退役）。
- **人类保送**（intent.endorsed）：人类可翻转一个 silent 决定——群聊里"@你说两句"的正式形态，执行链原样。
- **线程门控/预算/暂停/崩溃恢复**：原样。

# 3. 任务语境重写

意图指令从"会议发言申报"改为群聊观察者语境（codex/kimi `intentInstruction`）：*"You are a participant in an ongoing group chat. Given the latest messages, decide whether to reply. Staying silent is a valid choice; reply only when you have something to add."* 生成指令同步（直接回消息，不作"发言陈述"）。contextx 任务指令层的 cross 子轮标注随 ITC 退役删除。

# 4. 退役清单（拆除面）

| 退役项 | 理由 |
|---|---|
| set_policy 命令 / policy.changed 事件族 / PolicyParams（mode·max_speakers·λ·weights·reveal·rebuttals·auto_rounds·intent_window） | 无模式概念、无中央选人；存量 policy.changed 事件投影端忽略（回放容错） |
| reveal 三策略执行面（simultaneous 冻结揭示 / ITC + cross 子轮 / auto_index） | 群聊只有 sequential 语义（消息逐条出） |
| attention.Select 引擎接线 | 选人→自决；记分卡计算保留（band 透明 + 波内排序） |
| 快照 policy 区 / Timeline 的 round.\* 项 / TimelineItem.outcome·auto_index / SPA 模式选择卡 | UX 去轮次化 |
| directed 交锋链（窗口缩短/深度） | @点名前置 + 记分卡特征取代 |

response_cap（单条消息长度上限）与预算参数保留为引擎配置（非房间策略）。

# 5. 失败模式

- **评估风暴**：去抖闸（人类连发 N 条合并为一次评估）；连续发言由意图自决静默约束（agent 评估语境含自己刚发的最新消息）。
- **双 agent 对话环**：不设结构闸（附录 F：双边辩论是目标场景，无病理实录不设闸）——由意愿静默治理；若真机实录"互答不推进"的失控链，以内容级诊断（M3-4 echo/漂移签名）为精化候选，先取证再设闸。
- **崩溃窗口**：反应窗口为内存 timer——崩溃即静默（不重复开波，人类补发即续），与 v1.27 自动续聊同语义，登记非缺陷。
- **全员工况**：无 agent 席位 → 不开波、零事件。

# 6. 迁移

存量房间：事件日志不动（投影向前兼容——旧 round.opened 的多余字段 decode 忽略；policy.changed 忽略）；旧房间的 Timeline 在新投影下自然去轮次化。无数据迁移。

# 7. 开放问题

- OQ-A（随 M3；计划 v1.31 挂 M3-3 记忆层出口）：主动开口——静默 N 分钟后 agent 自行起话（MaiBot 式主动发言），依赖收束/记忆层给定"何时值得说"；落地后与意愿静默的交互需重验（发言冷却与对话环检测已先后退役——附录 D/F；三 agent 狗粮观测随 M3-1 基座启动）。**狗粮实证（2026-09-03，v1.44 登记）**：主动波按 5min 起搏正常，但评估语境无"未履行承诺"概念——agent 宣布"开拉数据"后，下一波及后续两轮主动波三席全静默空转，承诺无人履行（最新消息=自己的承诺 → "无事可添" → silent：防自言自语的同一语义同时杀死了自我续接；人类一句话即复活，实证）。由此明确：**"何时值得说"必须包含"我曾承诺未交付"状态**。**裁定（2026-09-03，负责人）**：未履行承诺的追踪**不是记忆系统，是 tasklist**——取常见 Harness 的 tasklist/todolist 形态，但在多 Agent 群聊形态上**必须加责任人字段**（每项任务归属到具体承诺者，否则"谁该交付"无从判定）；确定性派生优先（宣言模式 + N 波未交付即入清单）、人工门控；清单入评估语境供主动开口消费；与记忆层强关联（provenance 纪律同源，RFC-0007 §7.4）但独立成物。纯提示词级缓解（主动波语境明示"你 N 分钟前说过要做 X，有结果就交付"）仍为低成本候选，不预先堆机制，tasklist 落地前可狗粮试之。
- OQ-B：反应窗口时长是否暴露为用户设置（当前引擎常量 + dev 注入）。


## 附录 C：预算语义修订（v1.38 负责人裁定）

**裁定：token 成本只做统计观测，绝不进入任何主线门控。** 由此修订：

- 终止闸从四改三：意愿静默 / 发言冷却 / 对话环检测——**预算硬顶闸移除**（预算耗尽不再停波，agent 照常回应）；
- 意图评估的预算失格（ReserveOK）移除——意愿只由 agent 自决；
- 发布截断（ResponseCap/PublishGate rune 上限）移除——原文照发；超常输出由任务时长上限天然有界；
- 暂停胶囊的 budget 触发随闸移除（事件族保留，预留 human_pause 语义）；
- **统计面保留**：usage 入事件 metadata、账本重建（RebuildBudget）、调试面水位显示——成本可见、不拦截。

## 附录 D：结构冷却拆除与波内盲生成治本（v1.40 负责人裁定）

**裁定**：发言冷却（上一波发言者下一波跳过评估）整条拆除；滞后的治本位改为**逐发言人生成时语境刷新**。裁定动因：负责人质疑冷却必要性并提出滞后真身是"生成有延时、互相对答上一条"——机制分析证实滞后的来源不是波间陈旧锚（房间串行 + 开波重读最新锚，由构造排除；去抖只负责合并窗内突发，不覆盖此竞态），而是**波内盲生成**：开波时组装一份语境、全体发言人共享，同波后发者看不到先发者已发布的消息与波中人类插话。冷却在两 agent 房强制轮转只是掩盖了它，三 agent 房本就外漏。

由此修订：

- 终止闸从三改二（§2.3）：意愿静默 / 对话环检测；暂停随时掐断；
- **逐发言人生成时刷新**：每次生成前重读水位重组装——后发者对最新语境作答；锚点仍取本波原锚（刺激语义与因果链不变）；评估语境仍为开波快照（同时观察语义不变）；Receipt 任务号带发言序（`:gen0/:gen1…`）；
- 冷却的三道豁免补丁（@点名豁免、人类锚点全清、主动波豁免）随结构冷却消解；@点名保留排序前置 + 记分卡特征；
- 防自言自语移交意图自决静默（agent 评估语境含自己刚发的最新消息，echo 测试基线同步礼貌语义）；防无限互聊由环检测唯一硬闸兜底；
- 无 agent 席位 → 不开波（waveSkip reason：no_seats）。

**风险登记**：拆冷却后链终止依赖模型自决静默的可靠性——三 agent 狗粮观测（M3-1 基座）为持续验证位；若模型不自决沉默，环检测（≥6）为硬上界，代价是六条消息的冗余互聊。

**后续（同日，附录 F）**：对话环检测整体退役——本条"环检测为硬上界"的登记随之失效，失控风险的候选治理面改由附录 F 登记（内容级诊断，先取证再设闸）。

## 附录 E：对话环检测改形制导（v1.42，dogfood 实证修订）

**动因（真机数据）**：拆冷却后环检测从兜底变主闸，≥6 计数闸误杀健康讨论——实证房三方"来源审计"讨论（codex 承认未检索 → kimi 拉核验节点 → minimax 定锚一手信号 → codex 提醒二手来源 → kimi 自查 → minimax 第二批官方源）在第 6 条被切断；而打招呼链（三座各一条）由意愿静默自然收束，证明真实模型的自决静默工作正常。原病理（"双 bot 无限互相客气"）的形状特征是**封闭双声音循环**，不是长度。

**修订**：环检测从纯计数改为形制导——

- **闭环保龄短闸**：尾部连续 agent 消息 ≤2 说话人互答 ≥ `RingDyadTail`（默认 6）→ 收口（原病理形状，语义不变）；
- **绝对兜底**：任意形状 ≥ `RingAbsoluteTail`（默认 30）→ 收口（防三座永不静默的失控；跳波帧明示"发送一条消息即可继续"，人类一条消息重置尾部）；
- **多方轮转豁免**：≥3 说话人的尾部链不受短闸约束——讨论由意愿静默治理；
- 主动波排程条件同步改为 `!ringTripped`（修复 v1.40 隐藏退化：三方讨论超 6 条后主动波被旧计数静默禁掉）；
- 阈值入 `EngineConfig`（RingDyadTail/RingAbsoluteTail），归 OQ-B 设置族（M4 用户可调）。

**登记**：双声音且实质推进的正当两人讨论仍会被短闸在第 6 条——形状无法区分"互答"与"互相客气"；内容停滞判定（复用 M3-4 echo/漂移签名）为后续精化候选，待双声音误杀的狗粮实录再标定。

**后续（同日，附录 F）**：本附录机制未等到任何狗粮证据即被整体裁定退役——其动因记录（计数闸误杀健康三方讨论）本身即"无病理实录不设闸"的论据。形制导闸从落地到拆除不足一天，教训入档：**为预想病理调的参，每一次都砍在真实健康讨论上**。

## 附录 F：对话环检测整体退役（v1.43 负责人裁定）

**裁定（原文）**："如果不预先堆机制，应该把6条还有绝对兜底30条这些门控去掉，因为双边辩论也是允许的目标场景。"

**动因**：附录 E 的形制导闸落地当日即被狗粮误杀实录击中——三方讨论正欢时跳波帧提示"对话环收口"，健康交流被掐断（负责人实录："聊得正欢呢"）。复盘整条演化链：环检测原为"双 bot 无限互相客气"的**预想**病理而设（RFC-0003 时代），狗粮从未实录该病理；计数闸→形制导两次修订都是在为无证据的病理调参，而闸本身两次误杀真实健康讨论（三方来源审计、三方热聊各一次）。与 v1.38 去成本闸、v1.40 去冷却同一原则：**无病理实录不设闸**。

由此修订：

- 环检测整体拆除：闭环保龄短闸（RingDyadTail=6）、绝对兜底（RingAbsoluteTail=30）、ringTripped/尾部扫描函数、EngineConfig 阈值字段全部移除；waveSkip reason 收敛为 paused | thread_inactive | no_seats；
- 终止语义收敛为**意愿静默唯一结构闸**（§2.3）+ 人类暂停随时掐断；双边/多边长链讨论（辩论、审计、头脑风暴）均为目标场景，链长不设上界；
- 主动波排程条件简化为 `ProactiveSilence > 0 && 有席位`（附录 E 的 `!ringTripped` 条件随闸消解）；
- 失控风险移交：模型自决静默可靠性由三 agent 狗粮持续观测（M3-1）；若实录"互答不推进"的失控链，首选**内容级诊断**（复用 M3-4 echo/漂移签名，区分"互相客气"与"实质推进"）为精化候选——先取证、再设闸，闸的形状由实录标定，不由预想标定。

**测试面同步**：两个 Ring 专项 UT 退役；新增双边链持续 UT（种子 6 条双座交替链——旧短闸的病理形状——直接驱动反应波必须照常开波，钉死"双边辩论是目标场景"）；序列化测试改链持续断言（无界链 >6 波继续开）。**引擎测试卫生教训入档**：恒发言/礼貌互答适配器在无任何结构闸后是无界链，测试不关引擎即成僵尸——其评估回调会串扰后续测试（全局 evalHook 注入、Receipt append 竞争），一律 `defer eng.Close()`，捕获面读取一律等全链静默后。

## 附录 G：tasklist——带责任人的承诺追踪（M3-3 落地 v1.46；派生机制 v1.49 重做）

**定位（负责人裁定 2026-09-03，OQ-A 修订）**：未履行承诺的追踪**不是记忆系统**，是 tasklist——取常见 Harness 的 tasklist/todololist 形态，在多 Agent 群聊形态上**必须加责任人字段**（owner = 具体承诺者，否则"谁该交付"无从判定）；与记忆层强关联（provenance 纪律同源，RFC-0007 §7.4）但独立成物。

**派生（v1.49 重做：显式申报协议，替代 v1.46 宣言模式匹配；v1.50 增 @负责人 指派）**：v1.46 用自然语言宣言模式表（我来/我会/…）+ 疑问句排除做确定性派生，狗粮误报严重（假设句"如果是我我会用方案B"、引用、闲谈皆可命中）——负责人裁定（2026-09-01）：**不能通过关键字匹配来做**。改为显式申报协议：

- agent 在回复 body 末尾附 ` ```mosaic-todo ` 围栏块，块内逐行 GFM 任务列表语法：`- [ ] 事项` / `- [x] 已完成`；
- **@负责人 指派（v1.50）**：`- [ ] @对方 事项`——提出方（requester）=申报人，负责人（owner）=@者（负责人指令：任务的提出方和负责人得分开显示——A 指派 B 是群聊常态）。@解析：精确 participant_id，或 id 下划线分段不区分大小写唯一命中（"@kimi"→par_kimi_…）；歧义/未命中/指向人类 → 回退自领且 @前缀保留在任务文本里（信息不丢——负责人必须是 agent 座位）；
- 申报协议指令随语境常驻（tasklist_protocol，agent 须先知道约定才可能在首次承诺时申报）；
- 解析仍是确定性纯投影（零 LLM、零模型成本）：围栏标记即协议边界，正文里的自然语言**永不**派生——误报率结构性归零；
- **全量替换语义（v1.50 定域=提出方）**：再次申报的块即该提出方当前提出的完整任务集（自领任务 requester=owner 同属此集，他人派给我的任务不受我自己的块清算）——块内 (负责人,文本) 打 x = delivered、消失 = dismissed（撤回指派/收束）、新 [ ] 行 = 新 pending、保留行维持原任务（TaskID/债龄不变）；**负责人交叉结案**：负责人在自己块里对同文本任务打 x 即交差（A 派 B，B 打 x 结案）；块内 ≤12 行（容量纪律），归一化文本（空白折叠/去尾标点/截 120 字）跨申报匹配；多块最后一块生效，未闭合块容忍（模型截断兜底），零有效行的块不构成申报（防误触全量清空）；
- TaskID = 源事件 + 负责人 + 归一化文本哈希（tsk_ 前缀，确定性）；人类消息不派生（owner 的待办不是 agent 群聊语境的债）。

**生命周期（人工门控与自动结案并存，人工优先）**：pending → delivered | dismissed 有两条路——人类 resolve_task 命令（task.resolved 事件，human actor）与 agent 申报块内的 [x]/消失（投影内自动结案，ResolvedBy=申报人留痕——负责人交差记 owner、提出方结案/撤回记 requester）。两条纪律：人工裁定的终态**不被后续申报复活**（人工门控是权威；误报裁定后 agent 重申报同文本不新增）；agent 结案的终态可经重申报重开（新 TaskID——提出方撤回后重指派、负责人交差后重领）。波龄（申报后 round.opened 计数）确定性可算；waves_since ≥ 2 标 overdue。重复人工裁定拒绝（终态不可翻）。

**消费（语境注入）**：pending 任务入组装层 tasklist（owner/text/waves_since/overdue 最小投影，申报序——旧债在前）+ tasklist_protocol 常驻；主动波（proactive）额外注入承诺指令（tasklist_note：有未交付承诺者交付结果或说明进展）——OQ-A "我曾承诺未交付"触发源的承载物，v1.44 狗粮实证的"开拉数据"空转由治本。

**暴露面**：快照 tasks 投影（task_id/owner/**requester**/text/waves_since/overdue/status/note/resolved_*）+ SPA 任务 Tab（v1.50 重做为完整 tasklist 视图：进行中/已完成/已收束三段全量可见——此前只列"待交付承诺"与 tasklist 概念不符且已完成不可见；负责人≠提出方时显示"← 提出方 指派"徽标，结案方式区分 agent 申报/负责人交差/提出方撤回/人工裁定；波龄徽标、确认交付/移除按钮、点任务跳转申报消息）；agent 气泡内的申报块剥离渲染为"任务申报"芯片（协议是机器载荷，不入正文 Markdown）；resolve_task 命令（幂等+版本并发，同既有命令链纪律）。
