# 1. 动机与差距

v1.27 交付的自动续聊仍是"会议制"语义：轮是结构与单位，引擎是主持人（评估→选人→发言→散会，链按轮数上限收口）。负责人愿景是"群聊制"：**消息流是连续的，没有轮次边界；每个 agent 是群聊参与者，对每条消息自主执行 观察→判断→回复，沉默是自己的决定**。差距是交互模型级的，不是参数级的。

# 2. 模型语义

## 2.1 触发：去抖反应窗口（owner 裁定）

- 任何 `message.posted`（**人类或 agent**）落地即调度该房间的**反应窗口**（默认 3s，`EngineConfig.ReactionWindow` 可注入，测试可置 0）。
- 窗口内新消息到达 → 重置计时并**重锚**（以最新消息为锚）；到期后以"最新语境"开一个**反应波**。
- 去抖的理由：意图评估即一次 CLI 调用（10–20s + token）；严格逐条在人类连发或双 agent 快速互答时产生评估风暴。体感仍是逐条应答（窗口远短于生成时长）。

## 2.2 反应波（round 的内部化）

- 每波仍是事件流上的 `round.opened → intent.recorded* → floor.granted → message.posted* → round.closed`——**协议骨架不变**（事件溯源、epoch、CAS 迟到拒绝、崩溃恢复、预算账本全部原样生效），但 round 从用户可见结构降为内部记账：**快照 Timeline 不再收录 round.\***，仅开发者模式可见。
- 波内流程：对全部在席座位做意图评估（观察→判断）→ **action ∈ {speak, react} 者全部放行**（无 max_speakers、无中央选人）→ 按记分卡分排序 sequential 发布（**逐发言人生成时刷新语境**——后发者可见同波先发消息与波中人类插话；生成前按新水位重验，迟到围栏保留）→ 每条发布再开新窗口。
- **自决**：`silent` 是 agent 的合法决定，intent.recorded 全记录（R-01 保留——记分卡可查"谁选择了沉默"）。

## 2.3 终止与节流（附录 D 修订：结构冷却拆除，闸二道）

| 机制 | 语义 |
|---|---|
| 意愿静默 | 一波内全员 silent → `round.closed(quiescent)` → 不再开窗，流自然终止。**无轮数上限**（auto_rounds 退役） |
| 对话环检测 | 历史尾部连续 ≥6 条 agent 消息且无人类介入 → 不开新波（双 bot 无限互相客气的强制收口） |
| 暂停 | 人类随时掐断 |

## 2.4 保留机制（语义平移）

- **@点名**：被点名者发布前置 + 记分卡特征（B3 定向通道的群聊化简写，交锋链深度机制退役）。
- **人类保送**（intent.endorsed）：人类可翻转一个 silent 决定——群聊里"@你说两句"的正式形态，执行链原样。
- **线程门控/预算/暂停/崩溃恢复**：原样。

# 3. 任务语境重写

意图指令从"会议发言申报"改为群聊观察者语境（codex/kimi `intentInstruction`）：*"You are a participant in an ongoing group chat. Given the latest messages, decide whether to reply. Staying silent is a valid choice; reply only when you have something to add."* 生成指令同步（直接回消息，不作"发言陈述"）。contextx 任务指令层的 cross 子轮标注随 ITC 退役删除。

# 4. 退役清单（拆除面）

| 退役项 | 理由 |
|---|---|
| set_policy 命令 / policy.changed 事件族 / PolicyParams（mode·max_speakers·λ·weights·reveal·rebuttals·auto_rounds·intent_window） | 无模式概念、无中央选人；存量 policy.changed 事件投影端忽略（回放容错） |
| reveal 三策略执行面（simultaneous 冻结揭示 / ITC + cross 子轮 / auto_index） | 群聊只有 sequential 语义（消息逐条出） |
| attention.Select 引擎接线 | 选人→自决；记分卡计算保留（band 透明 + 波内排序） |
| 快照 policy 区 / Timeline 的 round.\* 项 / TimelineItem.outcome·auto_index / SPA 模式选择卡 | UX 去轮次化 |
| directed 交锋链（窗口缩短/深度） | @点名前置 + 记分卡特征取代 |

response_cap（单条消息长度上限）与预算参数保留为引擎配置（非房间策略）。

# 5. 失败模式

- **评估风暴**：去抖闸（人类连发 N 条合并为一次评估）；连续发言由意图自决静默约束（agent 评估语境含自己刚发的最新消息）。
- **双 agent 对话环**：环检测强制收口（无冷却后的唯一硬闸）。
- **崩溃窗口**：反应窗口为内存 timer——崩溃即静默（不重复开波，人类补发即续），与 v1.27 自动续聊同语义，登记非缺陷。
- **全员工况**：环检测命中或无 agent 席位 → 不开波、零事件。

# 6. 迁移

存量房间：事件日志不动（投影向前兼容——旧 round.opened 的多余字段 decode 忽略；policy.changed 忽略）；旧房间的 Timeline 在新投影下自然去轮次化。无数据迁移。

# 7. 开放问题

- OQ-A（随 M3；计划 v1.31 挂 M3-3 记忆层出口）：主动开口——静默 N 分钟后 agent 自行起话（MaiBot 式主动发言），依赖收束/记忆层给定"何时值得说"；落地后与发言冷却/对话环检测的交互需重验（三 agent 狗粮观测随 M3-1 基座启动）。
- OQ-B：反应窗口时长是否暴露为用户设置（当前引擎常量 + dev 注入）。


## 附录 C：预算语义修订（v1.38 负责人裁定）

**裁定：token 成本只做统计观测，绝不进入任何主线门控。** 由此修订：

- 终止闸从四改三：意愿静默 / 发言冷却 / 对话环检测——**预算硬顶闸移除**（预算耗尽不再停波，agent 照常回应）；
- 意图评估的预算失格（ReserveOK）移除——意愿只由 agent 自决；
- 发布截断（ResponseCap/PublishGate rune 上限）移除——原文照发；超常输出由任务时长上限天然有界；
- 暂停胶囊的 budget 触发随闸移除（事件族保留，预留 human_pause 语义）；
- **统计面保留**：usage 入事件 metadata、账本重建（RebuildBudget）、调试面水位显示——成本可见、不拦截。

## 附录 D：结构冷却拆除与波内盲生成治本（v1.40 负责人裁定）

**裁定**：发言冷却（上一波发言者下一波跳过评估）整条拆除；滞后的治本位改为**逐发言人生成时语境刷新**。裁定动因：负责人质疑冷却必要性并提出滞后真身是"生成有延时、互相对答上一条"——机制分析证实滞后的来源不是波间陈旧锚（房间串行 + 开波重读最新锚，由构造排除；去抖只负责合并窗内突发，不覆盖此竞态），而是**波内盲生成**：开波时组装一份语境、全体发言人共享，同波后发者看不到先发者已发布的消息与波中人类插话。冷却在两 agent 房强制轮转只是掩盖了它，三 agent 房本就外漏。

由此修订：

- 终止闸从三改二（§2.3）：意愿静默 / 对话环检测；暂停随时掐断；
- **逐发言人生成时刷新**：每次生成前重读水位重组装——后发者对最新语境作答；锚点仍取本波原锚（刺激语义与因果链不变）；评估语境仍为开波快照（同时观察语义不变）；Receipt 任务号带发言序（`:gen0/:gen1…`）；
- 冷却的三道豁免补丁（@点名豁免、人类锚点全清、主动波豁免）随结构冷却消解；@点名保留排序前置 + 记分卡特征；
- 防自言自语移交意图自决静默（agent 评估语境含自己刚发的最新消息，echo 测试基线同步礼貌语义）；防无限互聊由环检测唯一硬闸兜底；
- 无 agent 席位 → 不开波（waveSkip reason：no_seats）。

**风险登记**：拆冷却后链终止依赖模型自决静默的可靠性——三 agent 狗粮观测（M3-1 基座）为持续验证位；若模型不自决沉默，环检测（≥6）为硬上界，代价是六条消息的冗余互聊。
