# 1. 概述

## 1.1 简介

导出与删除是产品承诺（AR-010）：可导出 Room Event/Artifact 清单；按策略删除投影与对象、保留最小审计墓碑。本 RFC 定义：数据类别目录（权威 vs 派生）、各类保留默认值（OQ-07 建议）、导出格式（manifest + NDJSON 流式一致性快照）、删除级联链（事件 → 投影 → 向量 → 记忆 → 回执 → Artifact 引用）、墓碑契约（OQ-14 建议：只留 id/时间/依据，不泄露原属性），以及用户删除请求与法定审计保留冲突的分离策略。

## 1.2 动机

架构 §9.4 给出了隐私原则（级联删除、墓碑、opt-in），但保留默认值未定（OQ-07）、Receipt 的保留/导出/墓碑未定（OQ-14）、级联链无完整枚举。删除是"最容易做漏"的承诺——任何派生数据残留都是隐私违约；墓碑是"最容易做过"的承诺——元数据过富即泄露。两者都需要逐类别的精确契约。

## 1.3 目标

### 1.3.1 目标

1. 建立数据类别目录（权威/派生分类与删除语义）；
2. 定义各类保留默认值（OQ-07 裁决建议）；
3. 定义导出格式与一致性快照契约；
4. 定义删除级联链与墓碑契约（OQ-14 裁决建议）；
5. 定义用户删除请求与审计保留的冲突策略；
6. 定义观测数据的边界（不反哺业务权威）。

### 1.3.2 非目标

- 备份/PITR 与备份内已删数据的清除（运维侧，部署政策声明）；
- 观测后端自身保留（部署方）；
- 各类存储的物理清除实现细节（ADR）；
- 跨租户数据迁移（不存在此功能）。

# 2. 用例分析

| 用例 | 功能点 | 关键指标 | 安全隐私与 DFX 约束 |
|---|---|---|---|
| D-01 导出 Room | manifest + NDJSON 流式；含 Capsule/Memory/Receipt 清单与 Artifact 引用 | 10 万事件导出 < 5 分钟（流式） | 一致性快照（水位固定）；admin+ 权限 |
| D-02 用户删除请求 | 用户级删除级联（含历史发言处理策略） | 级联完成可追踪（任务状态） | 审计最小保留分离 |
| D-03 被引用事件删除 | relations/投影指向被删事件 → 墓碑边维持图完整性 | 图不断裂 | 墓碑不泄露原目标属性（8.3.2） |
| D-04 派生数据级联 | projection/embedding/memory/receipt 随源删除或重建 | 无残留（类别目录门禁） | 非干扰：删除后计数/水位不可推断原内容 |
| D-05 retention 到期 | archived Room 后到期处理（匿名化或删除） | 后台任务幂等重试 | 到期动作全审计 |
| D-06 删除 vs 法定审计 | 业务删除 + 审计最小集分离保留 | 依据代码化 | 部署政策声明优先（3.3.1） |
| D-07 墓碑非泄露 fixture | 墓碑化前后对无权主体响应一致 | CI 全绿（11.3） | 错误/timing 同样不可泄露 |

# 3. 方案设计

## 3.1 总体方案

### 3.1.1 数据类别目录

| 类别 | 权威性 | 删除语义 |
|---|---|---|
| room_events | 权威 | 正文删除 + 墓碑；顺序结构保留 |
| closure/pause capsules | 权威（事件派生但被接受固化） | 随引用事件策略；具名 dissent 归属处理 |
| artifacts 二进制 | 权威 | 引用计数归零后物理删除；hash 墓碑 |
| projections（结构/认知） | 派生 | 随源重建（删除后重放） |
| embeddings / memory_items | 派生 | 级联删除（不可留无源向量） |
| context_receipts | 派生审计 | 按 OQ-14 保留后删或墓碑化条目 |
| audit_records | 独立权威（合规） | 法定最小保留，不随业务删除 |
| observability（指标/日志/trace） | 运维 | 不反哺业务权威（7.3.4）；短保留 |

### 3.1.2 保留默认值（OQ-07 裁决建议）

| 数据 | 建议默认 | 说明 |
|---|---|---|
| room_events | Room 生命周期内永久；archived 后 90 天（部署方可配至无限） | 讨论资产默认长留 |
| audit_records | 180 天最小保留 | 与业务删除分离存储 |
| context_receipts | 90 天（OQ-14 建议） | 审计价值窗口与隐私平衡 |
| observability | 30 天 | 部署方可调 |
| memory_items | 随源 + 层级 TTL（默认 180 天，Thread 级 30 天） | 过期产生 memory.expired |
| artifacts | 随引用；quarantine 隔离区 14 天 | 命中恶意内容即策略清理 |

### 3.1.3 导出契约

- 格式：`manifest.json`（水位、版本、对象清单与 hash）+ `events.ndjson`（Envelope 原样）+ `capsules/ memory/ receipts.jsonl` + `artifacts.manifest`（引用 + hash + MIME，不含二进制；二进制按 signed URL 单独下载）；
- 一致性：导出绑定固定 event_watermark；导出期间 Room 可继续写入（增量不入包，manifest 声明水位）；
- 权限与审计：admin+（0008）；导出动作本身入审计（含范围与水位）。

### 3.1.4 删除级联链

```text
删除请求（用户级 / Room 级 / 管理员）
  → room_events 正文删除 + 墓碑
  → relations 指向该事件的边：保留边、目标改指墓碑（图完整性）
  → projections：标记受影响 → 后台按水印重放重建（不读已删正文）
  → embeddings / memory_items：级联删除（无源即删）
  → context_receipts：条目墓碑化（保留 run 维度计数骨架）
  → artifacts：引用计数 -1，归零物理删除
```

### 3.1.5 墓碑契约（OQ-14 裁决建议）

墓碑 = `{原 event_id（保留，维持边可解析）、deleted_at、legal_basis_code}`，**三字段之外一律不留**：不保留正文、原 visibility 之外的元数据、payload 摘要、大小暗示。约束：

- 墓碑对无权主体不可见（继承最小可见性）；
- 墓碑化前后，无权主体对图查询/投影的响应满足非干扰契约（计数不变化、错误/timing 一致）；
- Receipt 条目墓碑同理：保留 run 计数骨架、删除 ID 清单细节。

### 3.1.6 冲突策略

- 业务删除管道与审计保留管道**物理分离**（不同表/不同凭据）；
- 法定保留以 `legal_basis_code` 枚举（部署方登记）；冲突时审计保留最小集（who/when/what-kind），不含内容；
- 部署政策必须显式声明（3.3.1）；未声明时默认"用户删除优先、审计仅留最小骨架"。

### 3.1.7 观测边界

观测数据不可反向成为业务权威（7.3.4）；日志 fixture 不含 prompt/secret/PII 正文（11.3）；trace 采样默认保守、attribute 白名单（9.9 OTel 基线）。

## 3.2 技术选型

| 决策点 | 选择 | 放弃方案与原因 |
|---|---|---|
| 删除实现 | 软删 + 墓碑 + 异步物理清除 | 立即硬删：破坏图完整性与回放 |
| 导出 | 流式 NDJSON + manifest | 一次性 JSON 内存组装：大 Room 不可行 |
| retention 任务 | PG job/worker（复用 outbox 执行层） | 独立调度服务：无必要 |
| 级联正确性 | 类别目录门禁（新派生存储必须登记删除钩子，CI 检查） | 人工记忆：必然遗漏 |

## 3.3 功能与性能设计

- **内部端口原型**：`LifecyclePort: ExportRoom(room, watermark) -> ExportHandle / SubmitDeleteRequest(scope) -> task / ApplyRetention() / Tombstone(event_id, basis)`；
- **性能目标**：10 万事件导出 < 5 分钟（流式）；删除级联后台化、可断点续跑；retention 扫描不阻塞在线路径；
- **影响范围**：retention worker、导出/删除 API、全部派生存储的删除钩子、CI 墓碑非泄露 fixture。

## 3.4 安全隐私与 DFX 设计

- **无残留**：类别目录门禁 + 级联测试（删除后全库扫描无孤儿向量/记忆）；
- **非泄露**：墓碑三字段契约 + 双世界 fixture；
- **可审计**：导出/删除/retention 动作全审计（范围、水位、依据）；
- **完整性**：导出 manifest hash 校验；导入端可验证；
- **备份声明**：PITR 备份中的已删数据随备份周期过期——部署文档必须显式声明（不做备份内即时清除的虚假承诺）。

## 3.5 编程与调用设计

### 3.5.1 编程模型基本设计

- **开发环境**：删除级联 fixture（含墓碑边、投影重放、向量清零断言）；
- **开发约束**：新增派生存储必须同时登记类别目录行与删除钩子；
- **可验收设计**：三门禁——级联无残留、墓碑非泄露、导出可验证。

### 3.5.2 接口定义与设计

#### ExportRoom（命令）

接口描述：导出 Room 数据包（admin+）。

接口原型：`command_kind = "export_room"`

输入/输出参数：

| 参数名称 | 输入/输出 | 类型 | 描述 | 取值范围 |
| --- | --- | --- | --- | --- |
| watermark | 输出 | int | 快照水位（manifest 声明） | — |
| export_handle | 输出 | string | 下载句柄（异步生成完成通知） | — |

- 异常处理：导出任务失败可重试（幂等水位）。
- 约束说明：动作入审计；包内可见性按导出者权限。
- 变更说明：首版。
- 调用参考代码：（管理控制台。）

#### SubmitDeleteRequest（命令）

接口描述：用户/管理员提交删除请求（用户级或 Room 级）。

接口原型：`command_kind = "delete_request"`

输入/输出参数：

| 参数名称 | 输入/输出 | 类型 | 描述 | 取值范围 |
| --- | --- | --- | --- | --- |
| scope | 输入 | object | user / room / artifact 维度 | — |
| task_id / status | 输出 | — | 级联任务句柄与状态（可追踪） | — |

- 异常处理：与法定保留冲突时返回保留骨架说明（依据代码）。
- 约束说明：用户级请求只能由本人或 admin 发起。
- 变更说明：首版。
- 调用参考代码：（命令通道。）

#### 墓碑 Schema（RFC-0001 信封预留落地）

接口描述：墓碑对象的三字段契约（3.1.5）。

接口原型：`{"event_id": "evt_...", "deleted_at": "...", "legal_basis_code": "user_request"}`

- 变更说明：首版（随 RFC-0001 未决 5 联合关闭）。

### 3.5.3 编程手册设计

《数据治理与合规指南》（面向部署方）：保留默认值与调整、法定依据代码登记、导出包结构、备份内清除的真实语义、删除请求处理流程。

# 4. 缺点和风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 级联遗漏（新派生存储未登记） | 隐私残留 | 类别目录门禁 + CI 钩子检查 |
| 墓碑元数据过富 | 间接泄露 | 三字段硬契约 + fixture |
| 备份复活已删数据 | 合规风险 | 部署声明 + 备份周期对齐保留期 |
| 导出体积与耗时 | 运维压力 | 流式 + 异步 + 水位分片 |
| 审计保留与删除的法务边界不清 | 部署方违规 | 依据代码化 + 默认最小骨架 + 文档显式化 |

# 5. 现有技术

| 参考 | 借鉴 | 差异 |
|---|---|---|
| GDPR 第 17 条（擦除权）/ 第 20 条（可携带） | 删除与导出的权利形态 | Mosaic 是技术契约而非合规意见 |
| Event Sourcing 删除实践 | tombstone + 重建模式 | Mosaic 墓碑加三字段最小化约束 |
| 对象存储生命周期规则 | 版本化过期与清理 | 引用计数参与决策 |
| 数据分级分类（数据治理惯例） | 权威/派生分类驱动级联 | 目录门禁化为 CI 规则 |

# 6. 未解决问题

1. **OQ-07 终裁**：保留默认值表确认（尤其 events archived 后 90 天）。
2. **OQ-14 终裁**：Receipt 90 天保留与墓碑条目形态确认。
3. legal_basis_code 首批枚举集。
4. 用户级删除中"历史发言"的默认处理（正文清空保留墓碑 vs 整事件删）——建议正文清空。
5. 导出包加密与传输（含 Artifact 二进制的签名下载时效）。
6. 匿名化（anonymize）作为删除替代的适用条件。
