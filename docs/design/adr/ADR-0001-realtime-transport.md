# ADR-0001：客户端实时传输采用 SSE 下行 + HTTP 命令

| 状态 | Accepted |
|---|---|
| 日期 | 2026-08-25 |
| 关联 | RFC-0001 §3.1.3；架构 v0.6 §8.2.6 |

## 背景

客户端需要接收已提交事件投影、流式草稿与状态（AR-006，P95 < 1s），并提交控制命令（发言、暂停、取消）。架构基线原选 WebSocket，并以"客户端控制需另一路径"为由否决纯 SSE。

## 决策

- 所有客户端命令走幂等 HTTP API（RFC-0001 SubmitRoomCommand），控制类命令提升优先级队列（架构 §7.2.2）；
- 事件下发采用 SSE：`last_seen_seq` 续传，缺口走快照恢复（RFC-0001 §3.1.3）；
- typing/presence 等暂态上行信号用可丢失的 HTTP beacon，不建立持久双向连接。

## 后果与放弃方案

- 架构 §8.2.6 否决 SSE 的理由不成立：控制命令本就存在独立的幂等 HTTP 路径，无需 WS 承载；
- 放弃 WebSocket（coder/websocket 备选）：主流程无上行低延迟需求，省去 WS 库选型与连接运维；若 presence/typing 上行延迟成为体验瓶颈，以该条件触发升级，届时修订本 ADR；
- SSE 对代理/CDN 更友好、自动重连内建；断线恢复语义由 RFC-0001 承载，与传输解耦。
