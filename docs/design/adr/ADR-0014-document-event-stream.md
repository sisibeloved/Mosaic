# ADR-0014：文档作为第二权威事实源——per-doc 事件流（同一 SQLite 库）

- 状态：Accepted（2026-09-16，随 RFC-0014 裁定）
- 关联：[RFC-0014](../rfc/2026-09-16-rfc-0014-documents.md)（协作文档）、RFC-0001（Room Protocol，局部修订）、ADR-0008（个人版存储 SQLite）、ADR-0001（SSE 下行 + HTTP 命令）

## 背景与问题

架构基线（架构设计说明书）裁定 **Room Event Log 是唯一权威事实源**，全部房间行为进一条 per-room 追加日志。RFC-0014 引入全局文档资产后，两种落法冲突：

1. **文档事件进房间日志**：简单、不碰基线。但文档生命周期独立于任何讨论——讨论收束、房间删除后文档仍在，同一文档被多房间引用续作；且文档修订批会推进房间全局版本序列，与聊天写入互相制造 409（房间级 CAS 是现有唯一并发粒度）。
2. **文档自立事件流**：语义正确，但意味着出现第二个权威事实源，基线表述必须修订。

## 决策

- **每篇文档一条事件流**：`doc_events(doc_id, version, kind, payload_json, actor, created_at)`，`version` per-doc 单调递增——天然是文档级 CAS 序号与 SSE cursor。与房间日志**同一 SQLite 库、不同表**（ADR-0008 不变）：同事务跨表写入可行，备份 / 导出 / 墓碑设施天然覆盖。
- **基线修订**：架构基线的"Room Event Log 唯一权威"修订为"**房间日志与文档事件流并列为权威事实源**"——文档是生命周期独立于讨论的全局资产，其事实源随资产走；房间日志只记录关联事实（消息 doc_ref、`doc.attached_to_room` / `doc.detached_from_room`）。修订记录回填架构设计说明书 §0.3。
- **房间日志不受文档写流量冲击**：文档修订不推进房间版本序列，聊天 CAS 语义原样；房间流 SSE 不冗余转发文档事件（RFC-0014 §2.6 频道化）。
- **投影纪律不变**：文档当前态仍是事件流的纯函数折叠（可重建、可回放）；未来物化派生表仅是重建缓存（FTS5 / 墓碑派生表先例），不升格为权威。

## 后果与放弃方案

- 放弃"文档进房间日志"：避免房间版本序列被编辑流量污染、避免房间删除级联误删全局资产；代价是权威源从一变二——审计、导出、调试工具需同时理解两条流（debug 只读端点扩展 doc 面）。
- 恢复语义：崩溃重放对两条流各自成立；不存在跨流原子性需求（关联事实允许短暂滞后于文档事件，投影端容错）。
- 删除：房间删除不级联文档；文档删除级联清内容与索引、事件留痕（RFC-0014 §3/§4）。
- 云端形态演进时，doc 流可按 doc_id 分片迁移，与房间流无耦合——本决策不阻塞多人 / 多租户演进。
