# Mosaic v0.5.4 — Binding 任职状态机与交接（0.5 长期 Agent 与职责领域·第五件）

0.5.2 定义了职责，0.5.3 让它存在；本版交付**任职**：谁在承担某个职责实例——可审计的完整生命周期与交接。

## 新增

- **任职状态机**（RFC-0018 §3.2 / ADR-0021）：`preparing →（准入门）ready → active →（排空门）released`，准备失败 `→ blocked → preparing`；released 唯一终态留审计；非法转移一律 409 可见拒绝。建任职与重试均为单事务——中断/失败零残留。
- **单 active 不变量**（§13.5 / AT-13）：同一实例最多一位在任，由 SQLite **部分唯一索引**库级兜底——并发激活恰一胜者；冲突返回 409 `active_binding_exists`，绝不静默换人。
- **固定模板版本**（§5.2）：任职创建即钉住 `slot_spec_version`（省略取谱系最新；显式须在区间内，非法值拒绝而非静默替换）；模板后续演进不改变在任——升级 = 旧任职排空释放 + 新任职。
- **双门预埋**：准入门（0.5.5 能力核对/权限交集/readiness report）与排空门（0.6 在途工作处置）端口就位，当前恒通过/恒空；注入后即为真实 blocked/draining 语义（含未处置清单返回）。
- **任职前置校验**：Agent 须存在且 active（建任职与激活两时点校验——挂起/退役的 Agent 不接任职）。
- **交接位**：释放可携带交接备注（≤4KB），与状态、事件同事务入档；接续方经实例任职列表读取最近一次交接（按释放时间取最新）。
- **API 六端点**：建任职 / 激活 / 释放 / 列表（实例过滤）/ 详情 / 事件流（`binding_id` 主体）；写端点经生产写门。
- **设置页「任职」管理块**：在任者与钉住版本徽标、释放（交接备注输入）、就绪任职激活、建任职（Agent 下拉 + 钉版本）、最近交接展示。

## 修复（独立审校六项）

- **准备中断不再留下无法操作的记录**：建任职/重试改为单事务（终态直接落库 + 两事件一次提交）。
- **交接备注三处一致**：未上任直释与排空后补终段的备注随状态、事件同事务入投影。
- **显式非法版本号拒绝**：省略钉最新；显式 0/负值返回 400，不再静默绑定最新版。
- **任职事件主体字段修正**：事件以 `binding_id` 承载（不再借用 Agent 事件的 `agent_id` 字段）。
- **“最近交接”按释放时间选取**：不再显示创建序靠后的旧备注。
- **未加载任职不再误报“空缺”**：加载前与失败时使用中性提示。

## 升级说明

- v0.5.3 数据库首次启动自动建 `slot_bindings` / `binding_events` 表与单 active 部分唯一索引（migration v11），无需手工步骤；效果可在设置页「职责 → 实例 → 任职」与 `GET /v1/slots/bindings` 核对。
- 旧版本二进制可直接升级本库；回退不受影响（新增表对旧版不可见）。
- 设计基线：[RFC-0018](docs/design/rfc/2026-10-28-rfc-0018-personal-agent-swarm.md)（Approved）与 [ADR-0021](docs/design/adr/ADR-0021-binding-lifecycle.md)；后续 0.5.5 交付职责准入（能力核对、权限交集与 readiness report——准入门已在位）。
