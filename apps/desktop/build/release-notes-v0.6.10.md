# Mosaic v0.6.10 — 执行结果回房：返回通知（0.6 Mission 与本地执行领域·第十一件）

0.6.9 闭环了三事实（执行 ≠ 交付 ≠ 验收），但结果只存在于任务中心——交办它的房间对"送验了没有、验收过了没有、被退回还是取消了"一无所知。本件按 RFC-0018 §10.1/§10.2 把 Mission 结果回房：**先持久化、再通知来源房间**，并满足三条硬约束——持久（重启不丢）、去重（崩溃重投不重复）、Room 失效鲁棒（暂停保留、删除取消而结果保留）。四轮独立审校（9 + 1 + 7 + 5 项，含两项基线缺陷与两项历史数据补正）全部关闭后定版。

## 新增

- **通知源（ADR-0033 表 1）**：四类 `status_changed` 事实——`reviewing`（已提请验收）/ `accepted`（验收通过）/ `returned`（验收退回，含 0.6.9 初版 `to=returned` 老式事件）/ `canceled`（终局取消）。Run 级失败与 waiting 不回房（任务中心可见）；非房间交办的任务零通知。
- **投影（migration v25）**：`mission_events` 全局游标派生持久通知行（`mission_return_notices`——`source_seq` UNIQUE 即去重键）；卡片所需字段（当时契约版本、轮次、包、目标摘要）在事实落地那一刻快照定格，崩溃重启从游标重放不漏不重（AT-09 不变状态不反复通知）。
- **原子投递**：同一 SQLite 事务内"墓碑/暂停核对 + 追加 `message.posted`（actor `par_system` + `mission_ref` 封闭对象）+ 标记 delivered"——卡与标记同落，**去重由构造保证**；复用房间 outbox/FTS 同事务路径，SSE 与引擎照常消费（系统卡不触发讨论波——"不为回传自动恢复讨论"）。
- **暂停保留 / 删除取消 / 有界重试**：房间暂停 → `held`（不计次、恢复后按 `source_seq` 保序发布——每房每轮只投队首，暂停房积压不饿死他房）；房间删除 → `DeleteRoom` 级联取消待投 + `mission_sources.deleted_at` **来源墓碑**（结果与映射保留、不重跑任务，AT-20）；其余错误指数退避 12 次封顶 → `failed`（last_error 留痕，交付/验收事实不受影响）。
- **读面与契约**：`GET /v1/missions/{id}/return-notices`（每条来源事件恰一行——持久与去重可审计）；`MissionView.room_source` += `deleted_at`；`message.posted` 载荷 += `mission_ref`（系统 actor 专用，`post_message` 命令面拒收——人类不能伪造结果卡）。
- **SPA**：房间时间线把系统消息渲染为**引用卡片**（kind 徽标 + 任务卡 + 轮次，点击直达 `/missions?id=` 选中该任务；快照/实时两路同形）；任务中心详情「回房」区（状态徽章 / 房间事件 ID / 失败原因，独立轮询带乱序守卫）与来源房间已删除提示。

## 修复（四轮独立审校 + CI 揪出的基线竞态）

- **事实归属当时契约**：新事件的送验/裁定事务内写入实际契约版本与轮次；旧事件由投影按事件流回溯（`created` / `contract_revised` + 版本行目标快照 + 同包送验配对校准 + 全历史计数兜底）——v1 退回后修订 v2 的重放不把旧包标成 v2、不显示 v2 目标；取消恒第 0 轮；BOM 目标保留空摘要。
- **房首调度**：先取各房最早未完成通知、再判到期——同房不越序（恢复后按 reviewing → accepted 有序落卡），每房每轮一条。
- **删除链路**：migration v26 按 `room_tombstones` 原删除时间回填升级前已删房的来源墓碑；投递侧发现删除时兜底回填（同样取原时间）。
- **run 停止竞态（基线缺陷，CI macOS 实证）**：停止取消执行上下文后执行器返回的结果与停止信号在 `select` 双就绪——停止在场时迟到**成功正文不再发布**（只进 `late_result` 审计，AT-12）、迟到错误不再记 `failed`；已取出的结果交还收尾——迟到审计、租约释放恰一次，不空等停止宽限窗（取消后租约不再滞留到 TTL）。
- **前端时序**：快照与实时两路同形保留 `mission_ref`（刷新不丢任务链接）；台账与来源两请求独立更新、只丢弃比已显示更旧的响应、失败保留末次成功结果。
- **历史数据补正**：migration v27 首次重置回房投影游标全量幂等重扫——老式 `to=returned` 退回事件（0.6.9 初版形态）补发卡片，已投行与状态不动。

## 升级说明

- v0.6.9 数据库首次启动自动执行 migration v25–v27（幂等 DDL + 数据补正），无需手工步骤；停留在 v22–v24 中间形态的库同样可直接升级（v27 补投覆盖历史漏卡）。
- 无新增请求必填字段（裁定仍需 0.6.9 引入的 `review_round`）；老客户端对 `mission_ref` 字段按可选忽略。
- 设计基线：[RFC-0018](docs/design/rfc/2026-10-28-rfc-0018-personal-agent-swarm.md)（§10.1/§10.2、AT-09/AT-20）与 [ADR-0033](docs/design/adr/ADR-0033-mission-return-notice.md)（v0.4）。
