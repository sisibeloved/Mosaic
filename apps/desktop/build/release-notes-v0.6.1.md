# Mosaic v0.6.1 — 房间交办与 Dispatch 首切片（0.6 Mission 与本地执行领域·第二件）

0.6.0 让交办成为独立事实；本版把 Mission 与房间任务卡接通，并落地**轻量级智能体网关（Dispatch）首切片**——确定性解析 → 复核投递 → 回执的两段式骨架就此定型。

## 新增

- **房间来源唯一映射**（RFC-0018 §6.1 / ADR-0024，migration v14）：Mission 创建增可选 `room_source {room_id, task_id}`——房间与任务卡经真实投影校验（事件流 → 任务清单重建）；**(room_id, task_id) 全局唯一**：同一任务卡至多交办一次，撞键 409 `source_already_mapped` 回显已映射 mission_id；映射为创建事实，修订不可改（换来源 = 新交办）。
- **网关首切片**（RFC-0018 §4.4–4.8/§11.2/§11.2.1 的确定性子集）：`resolve` 只预检不创建（任一前置不满足 → blocked 决策携原因，恒 200；决策落库含请求全文与 SHA-256 摘要，10 分钟有效）；`dispatch` 复核决策（过期/目标变化 409 `route_stale` 重新解析）→ 执行**决策存档的请求**（不采信客户端重发内容）→ 建契约 + 回执；回执仅表示领域命令已提交，执行状态经 Mission 查询。
- **幂等语义**：`(caller_ref, scope, idempotency_key)` 库级唯一（caller/scope 服务端推导，请求体不得自称）——**幂等身份是请求摘要**：同摘要重试（含重新解析后的新路由）重放原回执；同键异载荷 409；**创建前原子认领**保证异摘要请求零副作用退出、并发孪生恰一认领；崩溃窗口经映射冲突可见恢复，不产生重复派单。
- **API**：dispatch 三端点（resolve / dispatch / receipts）+ mission 创建扩展（room_source）；resolve 与直接创建共用同一契约校验（必填存在性 + 显式预算严格界限——两条入口一致）。
- **UI**：房间任务卡「交办」入口（跳转预填来源）；任务中心创建表单增房间来源区（半填拦截）；契约详情来源徽标。

## 修复（独立审校 1 项 P1、4 项 P2）

- **同键并发冲突不再创建额外 Mission**：幂等键改为创建前原子认领两段式（认领绑定摘要 → 创建 → 完结），异摘要零副作用退出。
- **同摘要请求重新解析后可重放**：幂等身份从路由改为请求摘要；已提交回执查验先于决策时效（投递成功改变预检状态不夺重放）。
- **跨页历史不再丢失任务上下文**：来源查询跨页累积全量有序历史后统一重建（前页参与者索引不丢）。
- **来源半填不再静默丢失**：room_id 与 task_id 须同时空或同时非空。
- **Dispatch 不再绕过契约校验**：缺必填字段或显式全零预算一律 400，与直接创建一致。

## 升级说明

- v0.6.0 数据库首次启动自动建 mission_sources / dispatch_decisions / dispatch_receipts 三表（migration v14），无需手工步骤；旧版本二进制可直接升级本库，回退不受影响。
- 本版只交付交办关联与网关确定性路径：语义选择（AT-17）、事项续接、IM/事件入口随后续小版本按 RFC §13 阶段表接入；执行随 0.6.5。效果可在房间「任务」卡交办入口、任务中心与 `POST /v1/dispatch/resolve` 核对。
- 设计基线：[RFC-0018](docs/design/rfc/2026-10-28-rfc-0018-personal-agent-swarm.md)（Approved）与 [ADR-0024](docs/design/adr/ADR-0024-room-dispatch-first-slice.md)（含 ADR-0023 排布裁定的兑现）。
